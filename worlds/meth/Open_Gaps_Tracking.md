**13. Flagged so a future pass does not mistake a `corpus_index.py` non-hit for evidence that a passage isn't present.

**14. (2026-09-25) `cic/texts/AUTHORS.md` does not, and structurally cannot, include this world's three new author slugs (`wesley-john`, `wesley-charles`, `asbury-francis`).** That file is mechanically generated from CCEL-style `<DC.Creator>` XML markup (`corpus_authors.py`); none of this world's seven vendored files are CCEL XML (all are plain-text intake files with this project's own header-block convention instead). `corpus_map.py`'s own validator flags this as a non-blocking "finding" (11 occurrences, one per work-row using one of these three author slugs) rather than an error — consistent with how the same tool already treats every other plain-text-sourced author in this corpus (Luther, Zwingli, and others also do not appear in `AUTHORS.md`, for the identical structural reason, without special handling). Not a defect this build thread introduced or should route around; a standing, disclosed limitation of the author-index tool itself, worth the coach thread's attention if the corpus's own balance of CCEL-XML versus plain-text sources continues to shift.
