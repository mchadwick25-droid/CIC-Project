## 2. The classification question, answered

**Verdict: R7-3 is NOT an instance of the class escalated at OG-5.** It is a citation/labeling accuracy error — a wrong name attached to a right number — and it belongs with the single-locus descriptor corrections graded cosmetic at Rounds 3 and 4 (R3-3, R3-4, R3-6, R4-4) in *kind*, while remaining substantial in *grade* for the reason Round 7 gave. **OG-5 is not reopened. OG-6 can be closed on this determination.**

The reasoning, stated so it can be argued with:

**(a) OG-5's class has a defining predicate, and R7-3 does not carry it.** OG-5 defines its own class in its own words: *"a statement that a named structural unit of a vendored source … had been 'read in full' or 'now read,' when in fact only part of it had been."* The operative element is an affirmative predicate of **completeness** attached to a unit named by title. §13's cell carries no such predicate. It states an exact line range — 12100–12440 — and that range is true: those lines were read, every citation drawn from them is sound, and the same range is stated identically at §11 item 2, §11 item 8 and §13. Only the parenthetical gloss naming the range was wrong.

**(b) The mechanism that made OG-5's class dangerous is absent here, and Round 5 said so itself.** Round 5's own root-cause sentence, quoted at §11 item 8, names exactly why the escalated class survived five sweeps: *"two entries below named a section by title and claimed it 'read'/'in full' **without stating the actual line extent**, which is exactly how both findings survived Rounds 3–5's sweeps."* That is the operational definition of the class: a claim that cannot be falsified without first deriving the named section's true boundaries. R7-3 is the inverse case. The line extent *was* stated, exactly; anyone who did what §13's whole design invites — open the file at the stated lines — sees 340 lines of Part One, not three parts. The remedy Revision 5 was directed to apply ("every entry now states either an explicit locus (a narrow, checkable claim) or …") had **already been satisfied** by this cell. What failed was the human-readable descriptor bolted onto a compliant locus.

**(c) No coverage or warrant claim anywhere in the document ever depended on the label.** Before Revision 7, §11 item 2 read *"*Secular Authority* beyond 12100–12440 (R20) …"* and §11 item 8 read *"R20 (*Secular Authority*, 12100–12440, now read …)"*. Both declared the remainder unread; both stated the same narrow range. The document therefore never claimed, anywhere, that Parts Two or Three had been read. It contradicted itself between two locations — which is a real defect, and is why R7-3 is graded substantial — but a contradiction between a true locus and a false label is not the same object as an unfalsifiable completeness claim.

**(d) Nothing false could travel to the Registry.** The risk R5-1 named — a live route from Doc_03's overclaim into an APPROVED TO PROCEED canonical surface — runs through §11 item 8 only. §11 item 8's R20 line carried the narrow, true locus. What would have travelled was a wrong part-name in a parenthetical, not an inflated coverage claim. That is a materially different exposure.

**(e) "Part Four" does not exist, which is diagnostic.** A coverage overclaim is a false claim about a real thing — Article XXVIII exists and was partly read; the First Commandment exposition exists and was 57% unread. "Part IV" of this treatise is not a structural unit at all. No one can have over-reported reading it, and no coherent inflated claim can be assembled from it. The label reads as a corrupted or mistyped descriptor, not as an assertion about coverage.

**(f) The one argument on the other side, weighed and rejected.** The strongest case for inclusion is the harm test: a reader trusting §13's own read-record would believe Parts Two and Three were read, which *is* the harm OG-5 exists to prevent, and §13's discovery table is precisely the one of Round 5's four named locations no round ever swept for the class. That argument has real force, and it is why this review does not grade R7-3 down to cosmetic. But it proves the wrong thing. It establishes that R7-3 is a substantial defect in the same *location family*; it does not establish that it is the same *defect*. Classifying a finding into an escalated class because of where it was found, rather than what it is, would be the mirror image of the error OG-5 itself diagnosed — fixes scoped to where the last finding landed rather than to the claim type.

**(g) What would change this answer.** If a later round finds a §13 discovery-table cell that asserts completeness of a named unit **without** an exact line extent, or whose stated line extent is itself wrong in the enlarging direction, that is OG-5's class and OG-5 reopens on the same threshold Revision 4 set. **R8-5 below is the closest thing this round found, and it does not meet that bar either**: §13's v1 row mislabels which work 29 of its declared lines belong to, but the declared range is exact and nothing beyond it is claimed. It is R7-3's class a second time, not OG-5's.

**Nothing evidentiary turns on any of this, as at every round since Round 3.** Every locus drawn from v3 12100–12440 — 7.1's three, 8.5's, 3.2's, 2.6's and 7.2's — sits inside the range, is Part One material, and is correctly quoted.
