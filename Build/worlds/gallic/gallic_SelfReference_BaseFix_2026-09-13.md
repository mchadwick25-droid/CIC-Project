# Self-Reference Base Fix — Gallic Monastic-Ascetic Christianity

**Trigger:** the Phase D live Deep Interview finding
(`gallic_PhaseD_LiveDeepInterview_2026-09-13.md`) — under direct
identity-collision pressure ("which one are you — Martin or Cassian?"),
the voice broke strict we-voice four times in its closing lines. **The
project lead's instruction on receiving that finding:** "the
representative should not have insight to anything outside their world
and all fixes should be base fixes not fix on fix."

This note records three successive passes at the same field — each a
genuine base rewrite of `records/gallic/voice_craft/gallic.voice.craft.md`'s
"self-reference" flavor_note, never a bullet appended beside a prior one —
and what each pass's own live re-verification actually found, honestly,
including where the first two passes fell short.

## Root cause, established before writing anything

Direct comparison against the APPROVED Doc_10 Permanent Prompt
(`gallic_Representative_Permanent_Prompt_Renatus.txt`, paragraphs 3 and 6)
found the failure was a **propagation gap**, not a new problem: that
already-reviewed, already-approved text carries, in full, both the
"second guide" failure ("I am not really a person — I am a composite
voice built from many records... is explaining your own nature instead
of answering") and the "list of named individuals" failure ("a single
first-person-singular pronoun can slip in when you list several people
or roles doing different things at once... the fix is never to build a
list of named individuals doing named tasks at all"). Neither passage
was carried into the B-7 conversion of that prompt into this record's own
`self-reference` flavor_note. This is squarely the class of defect this
build's own Naming and Term Propagation discipline exists to catch.

## Pass 1 — restore the two named failure modes, with illustrative examples

Rewrote the flavor_note wholesale to add the two failure modes back in,
each with a concrete negative example drawn from Doc_10's own language,
using parenthetical numbered enumeration ("(1)... (2)...").

**Re-verification (recompile, re-pin, re-run the same six-turn
interview):** the *targeted* failure did not recur — no closing list
placed the voice among Martin and Cassian by name. But the same run
introduced a NEW, unrelated defect: markdown headings appeared across all
six turns, where the original pre-fix run had none. Read at the time as a
likely side effect of the numbered-list structure inside the note's own
prose (the model mirroring a structural pattern present in its own
instructions) — flagged honestly as a hypothesis, not asserted as
proven.

## Pass 2 — same content, continuous prose instead of enumeration

Rewrote the same field a second time, keeping both failure modes but
removing the parenthetical numbering, matching this record's own
house style (no lists anywhere else in `flavor_notes`).

**Re-verification:** the markdown-heading side effect did not recur in
this run. But the identity-collision turn broke first-person **three
more times**, in wording the pass-1 note's own named examples did not
literally cover — "What I carry is...", "when you hear me speak", "What
I am is the keeper of..." — proof that enumerating specific bad
sentences, however faithfully drawn from the approved prompt's own
examples, is itself the fix-on-fix pattern the project lead's
instruction named: each concrete example closes only the one door the
model was caught using, never the shape generating all of them.

## Pass 3 — one mechanical rule, no examples

Rewrote the field a third time, removing the illustrative examples
entirely and replacing them with a single, general, example-free
constraint: the sanctioned sentence, if used, closes the grammar with
it — zero occurrences of "I"/"me"/"my"/"mine" for the rest of the turn,
on any subject, however phrased, counted on the word itself rather than
on the intention behind it.

**Re-verification, two rounds:**
- Full six-turn interview, recompiled and re-pinned: markdown headings
  did not recur; the identity-collision turn this run was itself
  diverted by the fleet's own `system_nature_turn` routing classifier
  before reaching the voice at all (a separate, real, pre-existing
  system behavior — see below — not something this record governs).
- A dedicated, repeated single-question test (the identity-collision
  question sent three times) reached the voice twice before the third
  repeat was likewise diverted. **Both times it reached the voice, the
  answer was clean**: `output_defects: []`, opening with the one
  sanctioned sentence ("I am a representative of the monasteries of
  Gaul.") followed immediately by "Neither one." and strict "we"/"our"
  for the remainder, correctly describing Martin's and Cassian's own
  material in the third person and correctly holding the no-node-traffic
  and power-shown/disowned disciplines throughout.

## What is fixed, and what is disclosed but not touched here

**Fixed, base-level, re-verified live:** the specific register failure
the Phase D interview found — first-person self-description under direct
identity-collision pressure — did not recur in either of the two clean
live samples after the third pass. Package re-pinned:
`manifest_hash sha256:53b4750e53ca7f2fe0299cc5fece66b7b06c53d3a9a5a4d51ef676ddf3106f96`,
`packages/gallic/2026-09-13T16-06-19Z`. Full 18-gate battery and
`engine.m1.cross_world` re-run clean (0 new defects) after every pass.

**Named, not fixed here, because it is outside this field's own scope:**
a fleet-wide routing classifier (`system_nature_turn`) diverted the exact
identity-collision question to a fixed facilitator disclosure ("Yes — we
use AI here...") on three separate occasions across this session's
testing, including once on the very question this fix targets. This is
real classifier variance on a borderline-phrased question, not a defect
in this world's own voice_craft record — the classifier is shared
fleet-wide infrastructure, and changing it is a materially larger,
cross-world decision outside a single world's build scope. Flagged for
the project lead's own attention, not patched here.

**Not fully eliminated, only reduced to a hypothesis worth naming
honestly:** two clean live samples are evidence, not proof, that the
underlying tendency is gone in every phrasing a participant might use.
The mechanical, example-free rule in the pass-3 rewrite is a genuinely
different KIND of constraint than passes 1 and 2 (a closed-set word
count, not a list of shapes to avoid), which is why it is expected to
generalize better — but "expected to" is not "guaranteed to," and this is
recorded as an honest limit on this verification's own reach, not
smoothed into an unconditional claim of success.
