## What would make each class pass without weakening the check

Right now the tool accepts a quotation in exactly two ways: (1) the exact matcher (ellipses and bracketed insertions allowed) finds it in a `cic/texts` file cited in its paragraph, cited in its document, or assigned to the world; (2) a plain lower-cased substring test finds it in the project pool. That pool is `Build/worlds/_cross-world/**/*.md`, `Build/reference/**/*.md` without review-named files, `CLAUDE.md`, `cic-website/data/world-census.json`, `Build/reference/L1-Foundation/*.docx`, and the highest-numbered Framework .docx. It leaves out the world's own folder and its dossier. No marker in a document exempts a quotation. A `cic:<file>:<locus>` address is checked only after route (1) has matched; it then requires the match to sit inside that division. It never makes an unmatched quotation pass. The tool's note shows 0 quotations confirmed inside a cited address in these four documents.

**Class A (102).** Two kinds of change pass these honestly, and neither lowers the verbatim bar.

- *Tool, route (2) mechanics.* The fallback is a plain substring test, so any ellipsis, bracketed insertion or markdown emphasis fails, even against a document already in the pool (#9, #58, #129, #130, #131). Running the project fallback through the same `verify_quote_text` used for sources, and stripping `*`/`_` emphasis in `_norm`, applies the source rule to project documents. Nothing is relaxed.
- *Tool, pool coverage.* Most class-A sources are project documents the pool does not read: the Step 0 Methodology and Step 0 Conclusion .docx files in `Build/reference/L3B-World-Build-Methodology/` (the documents' own "Governed by" line names both); `cic/corpus-map/*.yaml` note fields; `cic/texts/README.md`; other worlds' `Build/worlds/<code>/` documents and `records/<code>/` records. The pool docstring's reason for leaving files out ("the same drafter ... would exempt itself") applies only to the world under check. Adding these files keeps that exclusion. Whether to add them is a methodology change, so it is the project lead's call.
- *Documents.* Five quotations come from the cic-build-cycle skill as it is installed outside the repo (#49, #52, #55, #91, #92). The repo copy, `Build/reference/method/skills/cic-build-cycle/SKILL.md`, has since been reworded. Re-quote them against the repo copy, or paraphrase them with a citation. Six quotations hold only in superseded text: the Donatism Step 0 draft on branch commit 4f420cbb (#13, #16, #17, #66, #89) and the pre-cleanup corpus-map note (#120). No change to the tool should pass these. Re-quote them against the current text, or take the quotation marks off and say the words were in a superseded version (commit named). Fix the WORDING rows (#98, #121) to the exact source words.

**Class A-own (22).** The tool shuts these out by design, and it should stay that way. Accepting the world's own files would let one drafter certify its own quotation. Paraphrase them with a section or line cross-reference, or quote the outside source that the lpc file itself quotes, where one exists. Fix the WORDING rows (#94, #107, #110, #148) to the exact words either way.

**Class B (4).** Fix #133 (drop the added "to") and #128 (quote only Zonaras's own words, without the nested straight quotes). Then add `cic:npnf104_augustine-anti-manichaean-anti-donatist.xml:<div id>` and `cic:npnf214_seven-ecumenical-councils.xml:xv.vi.ii`, so that each quotation is also tied to its division. #111 and #134 need the tool fix described above. Only after it would their addresses (`cic:npnf101_augustine-confessions-letters.xml:<Letter CCXI div>`, `cic:npnf104_...:<div holding v.vi.ix>`) have anything to confirm.

**Class C (65).** 55 are titles of secondary works in the Registry's Source column. Two options. (a) Tool: skip a quoted span that the Registry's own Source cell sets out as a citation title (closing quote, then comma, then a journal or volume), or that equals the `title` of the `records/lpc/source/` record the row names. A title is not a quotation of content, so skipping it removes no check on content. (b) Documents: set titles in a form the extractor does not read as a quotation. That changes the citation style, which is why (a) is the recommendation. The other 10 are labels, headings, scare quotes and hypotheticals (#40, #57, #78, #79, #81, #88, #108, #112, #114, #193). Italicise them or reword them without quotation marks. Teaching the tool to guess intent would weaken it.
