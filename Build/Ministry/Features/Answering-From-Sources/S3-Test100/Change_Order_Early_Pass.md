# Change order: an early records-only pass on the 106 questions

Ruled by Mark, 2026-10-31, relayed by the coordination thread. Decision-Log entry 35 records the ruling. This is a change order to the Stage 3 gate "Stage 2 done on lpc first": named, reasoned, and filed here, not a quiet edit.

## What changes

The 106-question run (`lpc_106_questions.yaml`, seal in `lpc_106_questions.sha256`) starts now, before Stage 2 has landed on lpc. It is named an **early pass, not the Stage 4 proof**, in every report, sheet and log that carries its numbers.

- It reads records only. Context for the voice comes from line windows around each record's cited lines in the vendored texts, not from Stage 2 output. The run reads no Stage 2 file.
- Shadow only, free, in-plan. No metered model call. Voice drafts, classifications and every judge read are made by Claude Code helpers inside the plan.
- Sealed probes are handled by id only. The work directory lies outside the repository, so no probe wording reaches the repo.
- Nothing is promoted and no gate is retired by this pass.

## What does not change

The real proof reruns after Stage 2 lands on lpc, exactly as the Stage 3 and Stage 4 orders say. This pass does not satisfy that gate and its numbers are not carried forward as the proof.

## Order of work

The run goes first and the lpc absence scan (OG-118) follows it, per Mark's ruling.

## Why

The run needs nothing from Stage 2, and waiting would hold back what the fit step, the story lengths and the judges can already show. The cost of running early is that the numbers describe line-window context, not Stage 2 context, which is why they are labelled as they are.
