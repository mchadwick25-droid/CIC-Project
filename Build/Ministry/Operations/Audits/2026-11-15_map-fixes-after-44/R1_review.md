## What holds

- **A. Era mark.** It is placed from `getBBox()` on every `pinEraCaptions` run, after the transform is set, so it follows what WebKit actually draws. That removes the stale ratio taken before the font loads, and the assumption that width scales in a straight line with font size. The ResizeObserver covers the late Cinzel swap with no `loadingdone` event. `render()` disconnects it before rebuilding, and it is defined before the only `render()` call.
- **B. Every path reaches the clamp.** zoomToWho, goIntoEra, focusWorld, showConnections, centerView, zoomAt, wheel, drag, nudge, Home/End, glide, touch pan, pinch, pinch end, resize and the deep link all end in `applyTransform`, so all pass `clampView`. zoomAt and pinch clamp the scale, then anchor at the cursor or the fingers, so there is no jitter at the floor. A drag holds no leftover distance at the wall. The glide stops per axis at the wall.
- **C. Clamp maths.** `clampAxis` is right. Its centring branch runs only when the tree is narrower than a third of the screen, which no floor allows. Floors: desktop 1440×900, 0.454 (opening 0.504); 1920×1080, 0.545; iPad portrait, 0.352; iPad landscape, 0.414; iPhone 13, 0.183 (opening 0.391).
- **E. Tip gate.** It matches iOS's event order: pointerover and pointerdown (touch) come before the compat mouseenter and focus. Every `showTip`/`showTipAt` path is gated, and nothing else writes `#tip`. Mouse hover, keyboard focus, pen and hybrid devices behave as in release 44.
- **H. Hygiene.** No commentary or change history added to `index.html`.

## Findings

1. **MINOR. Rotation can leave the wrong detail mode.** `cft-website/index.html:122139` (resize) with `clampView` at 121810–121813. On resize, `clampView` can raise the scale, but `applyDetail` is not called. An iPhone at its 0.183 floor turned to landscape gets a floor of 0.352, above `DETAIL_THRESHOLD` (0.34). The rivers stay plain and the labels stay hidden until the next zoom. Fix: call `applyDetail()` after the clamp.
2. **MINOR. The mark's place on leaving the era strip rests on the ResizeObserver alone.** 121823–121824. `applyTransform` runs `pinEraCaptions` before `syncEraStrip` removes `strip-on`. While that class is set, `#era-labels` is `display:none`, so `getBBox` reads zero and the mark is placed at the title's start. Only the observer firing (size 0 to the real width) corrects it. Zooming out across 0.8 is untested. Fix: run `syncEraStrip()` first.
3. **MINOR. Extra measuring work on every frame.** 121651–121659, 121645. Each title is written and then read in turn, so drag, pinch and glide force up to 10 synchronous layouts a frame. Where the font size in map units changes with scale (below about 0.58 and above about 0.85, the whole phone range), the observer also fires on every zoom frame and runs `pinEraCaptions` a second time. Fix: write every title, then read every box, then place the marks; have the observer re-pin only when a size differs from the one just measured.
4. **MINOR. Closing the Who list does not re-clamp.** `renderTray` at 120411 calls `pinEraCaptions()`, not `applyTransform()`. `mapView().l` changes when the tray shows or hides. After `clearWho` on desktop, the left side can be up to about 690 px empty of 1440 until the next move. Fix: call `applyTransform()` there.
5. **MINOR. The iPhone floor is not "a little below the opening zoom".** `minScale`, 121800. It is the width fit, 0.183, which is 47% of the opening zoom (0.391), not 90%. On phones the brief's two conditions cannot both hold, because the opening is raised to 0.391 and the tree is wider than the screen there. The test's lower bound (`>= open*0.4`) was set to pass this. Fix: no code change if the width fit is wanted, but it is Mark's choice and should be named to him, not left in a test bound.
6. **MINOR. iOS may hold back the first tap (unverified on a device).** 120727–120731, 120853, 120910, 120794. Only the tip is gated. The compat mouseenter still sets the halo opacity, `litMovement` and edge opacities. WebKit's content-change observer can hold the click when hover visibly changes content, so a second tap might be needed. Fix: check on an iPhone; if so, gate the hover effects the same way.
7. **MINOR. A pinch on the controls over the map can still zoom the page.** Lines 311, 41, 346; DOM 501–516. `#eraStrip`, `#zoomCtl`, `#connChip`, `#whoTray` and `#zoomHint` sit outside `#stage`, so a pinch starting on them is not cancelled. The era strip is a full-width band at zoom 0.8 and above. Also, `touch-action:none` on `#stage` (line 65) was already on origin/main; the commit message's claim that it was added does nothing. Fix: give the map's controls the same two-finger and gesture-event cancelling; leave text and card surfaces alone.
8. **MINOR. Test gaps.** `Build/tools/tree_map_view.test.mjs`; `.github/workflows/ci.yml:370`. CI does not run the new test. The late-font test needs `fonts.gstatic.com` reachable. The "page did not zoom" check would also pass on origin/main (Chromium already honours `touch-action:none`); only the synthetic gesture-event check tests new code. These fail on origin/main: the short-measure test, the late-font test without the event, the drag/wheel/key/fling clamps, the floor and the tap tip. Untested: rotation or resize, closing the Who list, zooming out across 0.8, and the keyboard focus tip still showing. Fix: add those cases; run the test in CI with Playwright Chromium, or record why it is local-only.
