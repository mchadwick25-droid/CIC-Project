## The change

- `app/rag/query_rewrite.py`: ONE Haiku call producing a standalone,
  **world-aware** retrieval query for reactive turns — fail-open (any
  failure returns the legacy concatenation, degrading to exactly the old
  behavior). Wired into `_prepare_representative_turn`, replacing
  `f"{participant}\n\n{name} just said: {other_turn}"`.
- **The bridges' fix turned out deterministic — better than the spec:**
  the modern-term bridge already extracts the underlying subject, and the
  epistemology bridge already holds the participant's own original
  question. Each now sets `retrieval_query_override` on the working
  state (consumed once by the turn-prep), so retrieval searches the real
  subject instead of handback boilerplate — zero extra LLM calls for the
  bridge paths.
- `cross_encoder.py`: the reactive-marker lenient floor is retired — the
  concatenation shape it compensated for no longer exists.
- Harness: reactive golden cases carry committed **fixture rewrites**
  generated once from the real rewrite path (fixture-from-live), keeping
  the harness deterministic. Fixture generation itself caught and fixed
  two real prompt defects before anything shipped:
  1. v1 folded the *previous speaker's world's* institutions into the
     query ("house-churches" driving a Desert search) — measured as a
     Desert reactive drop;
  2. v2's fix leaked sideways (Syriac vocabulary in an Alexandria query)
     — fixed structurally by making the rewrite **world-aware** (the
     target world's name is in the prompt; the runtime passes the
     current world's config name). v3 fixtures are clean in all six
     worlds.
