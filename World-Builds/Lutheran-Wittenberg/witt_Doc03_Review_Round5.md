# Root cause

Three rounds diagnosed a defect class; three fixes were each scoped to *where the last finding landed* rather than to *the claim type*:

- Round 2 fixed Neve's introduction → Round 3 found the same defect in five more items of the same list.
- Round 3 swept the list → Round 4 found two more items **inside** that sweep.
- Round 4's finding was "re-derive every remaining claim in §12" → Revision 4 did exactly that, correctly and verifiably, **and the same claim about the same work survived one item below, in §11.**

The scope has widened each round (one item → one list → one section), but it has never once been set by *the kind of claim*. The claim type is: **any statement in this document that a named structural unit was read.** Those live in at least four places — §12's two lists, §11 item 2's unread enumeration, §11 item 8's Registry-maintenance proposals, and §13's discovery table — and only §12 has ever been swept as a whole.

A sixth patch that fixes R5-1 and R5-2 would repeat the error a fifth time. What the evidence supports is a single pass that enumerates **every** "read"/"in full"/"now read" claim in all four locations, re-derives each against the next structural heading, and reconciles the four lists against one another — with §11 item 2's unread enumeration derived *as the complement of* the read ranges rather than written independently, since that is where both of this round's findings actually hide.
