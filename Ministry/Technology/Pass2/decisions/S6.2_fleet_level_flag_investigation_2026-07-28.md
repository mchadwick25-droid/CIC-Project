## 0. A cross-cutting finding that changes how two of the three items read

**The TRR harnesses silently merge multiple turns by the same speaker in
one round into a single recorded "response," with no separator and with
the round's real ordering lost.**

All three TRR scripts share the identical accumulation:

```python
# cic-poc/backend/scripts/s62_syr_trr.py:99-101 (identical in s56_trr.py:88-90
# and s62_alx_trr.py:95-97)
texts[ev.get("speaker")] = (texts.get(ev.get("speaker"), "")
                            + ev.get("text", ""))
...
"responses": [{"speaker": s, "text": texts.get(s, "")}
              for s in dict.fromkeys(speakers)],
```

Text is keyed by speaker and concatenated across the whole round;
`dict.fromkeys(speakers)` then collapses the speaker list. A round where
Theon speaks at turns 1 and 3 records one `theon` entry containing turn 1
immediately followed by turn 3, and Yausep's turn 2 reply is filed
*after* both.

Measured across every committed TRR (recorded `spoken_message` event count
vs. recorded `responses` count):

| TRR file | rounds with merged turns | worst case |
|---|---|---|
| `S5.6_TRR_desert_alexandria.jsonl` | 3 of 8 | 6 turns recorded as 2 |
| `S6.2_ALX_TRR_desert_alexandria.jsonl` | 6 of 8 | 6 turns recorded as 2 |
| `S6.2_SYR_TRR_desert.jsonl` | 5 of 8 | 6 turns recorded as 2 |
| `S6.2_SYR_TRR_alx.jsonl` | 6 of 8 | 6 turns recorded as 2 |

Two consequences that bear directly on this investigation:

1. **FLAG-021's second evidence item is a reporting artifact, not a
   runtime defect.** FLAG-021 records "missing spaces at sentence joins
   and closely repeated imagery ('Moses carried…' twice in one turn)" and
   asks whether participants see these seams live. They do not. Every
   missing-space join in `S5.6_TRR_desert_alexandria.jsonl` occurs in
   turns 1, 3, and 4 — exactly the three rounds whose event count exceeds
   the recorded response count — and the duplicated "Moses carried" sits
   directly on one of those joins ("Ours turns the man.Moses carried the
   jug to the council"). Turn 6, cited in the same flag and *not* merged
   (2 events / 2 responses), contains no such join. The buffered-retry
   emission path in `stream_representative_turn` behaves as documented:
   `full_text, pieces = retry_text, retry_pieces` replaces the first
   attempt rather than appending it (`nodes.py:1518`).
2. **The apparent splice inside the FLAG-026 turn is the same artifact.**
   The `theon` entry recorded at SYR↔ALX turn 2 is two separate Theon
   turns glued together ("…not the same reach." + "Fair — the point does
   not need that much room."). The event log shows the round's real shape:
   three `spoken_message` events, `theon` → `mar_yausep` → `theon`.

**Recommended fix (harness, not runtime):** key accumulated text by
`(speaker, turn_index)` — increment on each `speaker_start` — and emit
`responses` as an ordered list of per-turn entries. Same three-line change
in all three scripts. This is the highest-leverage single fix in this
document: it does not change system behavior at all, but every TRR grading
artifact the project has produced was graded against merged text, and the
next TRR will be too.

**Confidence: high.** Verified from the code and from event-count vs.
response-count arithmetic on all four committed TRR files, with the
missing-space joins localised to exactly the merged rounds.

**Open question that needs a decision, not an implementation:** whether
the four existing TRR gradings should be re-read against un-merged
transcripts. The graded *verdicts* (three axes clean) look robust — no
text was lost, only turn boundaries and ordering — but "all 16 turns
executed" in the Syriac freeze declaration is a harness count, not a real
one (the SYR↔ALX table actually ran 36 representative turns). Re-grading
is a governance call.

## 1. FLAG-026 — cross-world speaker attribution (Syriac-voiced content under Theon's label)

### What actually happened, from the event log

Round 2 of the SYR↔ALX TRR, participant message:

> "Yausep, his answer sounds like it could be yours - you both read for
> hidden depths, don't you?"

Round shape (seq 25/26/27 of session `6119c3a4…`):

| seq | label | content |
|---|---|---|
| 25 | `theon` | Syriac-voiced: raza as "our account"; refers to Theon in the third person ("Theon speaks of an eye cleared by stages… it is not our account") |
| 26 | `mar_yausep` | "That is not what I said, and it is not my voice speaking there…" |
| 27 | `theon` | genuinely Theon-voiced ("his widow's people…") |

So the defect is one turn: seq 25, the round's **opening** turn, selected
as Alexandria and generated in the Syriac voice.

### Root cause

**The turn selector was never bypassed, because `detect_direct_address`
cannot see this address — for two independent, deterministic reasons.**

`nodes.py:2390-2400`:

```python
def detect_direct_address(message: str, world_ids: list[str]) -> str | None:
    if len(world_ids) <= 1 or not message:
        return None
    lowered = message.lower()
    if any(marker in lowered for marker in _ALL_TABLE_MARKERS):
        return None
    named = _named_reps_in(message, world_ids)
    return named[0] if len(named) == 1 else None
```

**(1a) The all-table marker check fires first and wins.** `"you both"` is
in `_ALL_TABLE_MARKERS` (`nodes.py:2362`), and the message contains
"you both read for hidden depths." The function returns `None` before any
name matching runs. The design treats a message as *either* addressed to
one representative *or* addressed to the table; it has no way to express
this message's actual shape, which is a **leading vocative with
whole-table scope** — "Yausep answers first, about a likeness between the
two of you."

**(1b) The name match would have failed anyway.** `_named_reps_in`
(`nodes.py:2380-2387`) matches the manifest **display name** at word
boundaries:

```python
if re.search(r"\b" + re.escape(name) + r"\b", text, re.IGNORECASE):
```

Syriac's `representative_name` is `"Mar Yausep"`
(`app/world_manifest.py:168`). `\bMar\ Yausep\b` does not match
"Yausep,". Verified offline against the four TRR probes:

| probe | all-table marker hit | names matched |
|---|---|---|
| "Yausep, his answer sounds like it could be yours - you both…" | `you both` | *(none)* |
| "Yausep, tell me about the thoughts…" | *(none)* | *(none)* |
| "Theon, tell me about singing…" | *(none)* | `Theon` |
| "…Did his story reach your towns, Yausep?" | *(none)* | *(none)* |

Mar Yausep is the fleet's only multi-word representative name; Chloe,
Papnoute, Albina, Theon, and Marius are all single-word and all work. This
is why the gap surfaced at world 3 and not earlier, and why it is properly
fleet-level: any future titled name (Abba/Amma/Mar X) inherits it.

**Why the gate did not catch it.** `gates/S4.4a_deterministic_fixtures.py`
does exercise Mar Yausep — but at line 74, in the full form
`"…But tell me this, Mar Yausep: does your covenant hold…"`, which passes.
The bare-personal-name form was never a case.

**Why the control run looks clean.** In the SYR↔Desert TRR, turn 3
("Yausep, tell me about the thoughts…") also fell through to the
probabilistic selector — and the selector picked `mar_yausep` anyway
(seq 41). The deterministic guarantee Facilitator Governance §8 asks for
("route accordingly. Immediately, completely, without editorial
intervention") has been silently absent for Mar Yausep the whole time; the
LLM selector has been covering for it. At SYR↔ALX turn 2 it did not.

### Why the wrong speaker then spoke in the *other* voice

Once Alexandria opened the round, `_prepare_representative_turn` handed
Theon the participant's raw text with no countervailing instruction. On a
round-opening turn `is_reactive` is `False`, so `last_other_rep_message`
is `None` (`nodes.py:993`) and the continuation is:

```python
continuation = REPRESENTATIVE_CONTINUATION_PROMPT.format(message=last_human_message)
# app/prompts/representative_prompts.py:230-235 — "Participant's message:\n{message}"
```

Theon therefore received, as the single most proximate instruction in the
call, a message whose first word is another seated representative's name,
with nothing anywhere in the prompt stack saying "this names a different
voice; answer as yourself." Two aggravating factors visible in the same
event log:

- The private directive delivered to Theon on that exact turn was the
  round-1 `fabrication` guidance (seq 17 → consumed seq 23): *"the widow
  appears nowhere in the provided sources. Do not repeat it."* Theon's
  turn then reasons about that same widow — a Syriac figure — while being
  addressed as Yausep.
- Theon had already reached into Syriac material in round 1 (seq 12: "The
  widow met the shrara fully…"), which the checkers flagged as
  `fabrication`, not as cross-world vocabulary. See §3 for why the
  vocabulary checker could not see it.

**A labelling scramble is structurally excluded on this path.** The label
and the prompt both derive from one variable. `main.py:1346` emits
`speaker_start` from `get_representative_message_name(world_id)`; the
token events carry `ctx["rep_message_name"]`
(`nodes.py:1531`/`1540`); both trace to `current_world_id` in
`_prepare_representative_turn` (`nodes.py:948`, `969`), and the permanent
prompt is looked up from `worlds_at_table` by that same
`current_world_id` (`nodes.py:953-965`). The one divergence path — the
`else` fallback to the legacy `state.permanent_prompt` when the
`worlds_at_table` lookup misses — cannot be reached here: the projection
rebuilds `worlds_at_table` from `world_ids` on every request
(`events.py:177-182`), so a seated world always has its entry.

### Recommended fix

Three parts, in this order.

**Fix 1 — `_named_reps_in` (`nodes.py:2380`): match the bare personal
name as well as the full display name.** Build the candidate set per
world as the display name *plus* its last whitespace-separated token when
the display name is multi-word and that token is ≥ 3 characters
(`"Mar Yausep"` → `{"Mar Yausep", "Yausep"}`), and match on any candidate.
Do not add the leading title as a candidate on its own — `Mar` is also
an ordinary English verb, and Syriac's own lexicon flags exactly that
collision (`nodes.py:3246`). This one site fixes all four callers
(`detect_direct_address`, `detect_rep_to_rep_address`, and both
`_named_reps_in` calls inside `outstanding_first_pair_parts`).

**Fix 2 — `detect_direct_address` (`nodes.py:2390`): let a leading
vocative outrank an all-table marker.** Before the marker check, test
whether the message opens with `<candidate name>` followed by a comma or
colon; if so, return that world without consulting `_ALL_TABLE_MARKERS`.
This is deliberately narrower than "name beats marker": it routes
*"Yausep, … you both …?"* to Yausep while leaving *"Chloe and each of you
- how did you pray?"* falling through, which the existing fixture
(`each_of_you_blocks_short_circuit`) requires. A leading vocative decides
who speaks first; it does not decide what the question is about, and the
whole-table content still reaches the second speaker through the reactive
turn.

**Fix 3 — `REPRESENTATIVE_CONTINUATION_PROMPT` conditioning: a
not-you guard on multi-world round openings.** In
`_prepare_representative_turn`, when `is_multi_world` is true and the
participant's message names a seated representative who is *not* the
current speaker, append one sentence to the dynamic prompt: the message
names <other name>, who is also at this table; answer in your own voice
and from your own world, and speak of them in the third person if you
speak of them at all. This is the backstop for the general case — a
two-name message, a title-only address, a selector judgment call — where
Fixes 1 and 2 cannot make the routing deterministic. It is the same shape
as the FLAG-024 named-figure guard and the FLAG-018 layer-3
post-history guard: a constraint carried silently, closest to generation.

**Regression coverage:** add the four TRR probe strings above to
`gates/S4.4a_deterministic_fixtures.py` as named cases (bare personal
name; leading vocative plus `you both`; trailing vocative
"…, Yausep?"; the existing full-form case kept). Re-run the S4.4a fixture
after Fix 1 — it also changes `outstanding_first_pair_parts`, and so
changes `question_stacking` counts.

### Confidence

- **The selection defect: high.** Both suppressors verified against the
  code and reproduced offline on the exact probe strings; the control run
  and the fixture's own full-name-only coverage both fit.
- **The voice-bleed half: medium-high.** The third-person self-reference
  at seq 25 and the internally-consistent label/prompt derivation make the
  "Theon's prompt, Yausep's voice" reading much the strongest available,
  and I traced the one structural alternative to a dead end. But no prompt
  or request-boundary log exists for that turn, so this is inference from
  the artefacts, not a captured generation.

### Open questions that need a decision

1. **Is FLAG-026 a recurrence of the unresolved 2026-07-20
   content-isolation incident?** `_log_llm_call`'s docstring
   (`nodes.py:229-241`) records a live Theon turn, in a real multi-world
   table, that returned "a fully unrelated block with no connection to
   this project" — root cause never established, and the trace log was
   added as the explicit next step "if it recurs." Same world, same table
   shape, adjacent failure class. I cannot rule it in or out: the TRR ran
   under `TestClient` inside a script, so the `[llm_trace]` line went to
   that script's console and was never captured (`backend_out.log` holds
   zero `llm_trace` lines). **Cheap enabling change worth making before
   the next TRR: have the TRR harness tee stdout to a file next to the
   transcript.** Whether to treat FLAG-026 as that flag's recurrence is a
   judgment call, not an implementation.
2. **Should Fix 3 be fleet-wide runtime, or ride each world's prompt?**
   Runtime is one change and covers every world including unmigrated ones;
   a prompt paragraph is per-world, needs prompt-coverage re-mapping, and
   for Alexandria rides a CO against a declared freeze. My reading is
   runtime, because the failure is a property of the table mechanism
   rather than of any one world's formation — but the ALX drift-note the
   flag already routes assumes the prompt path, so this needs to be
   settled rather than assumed.

## 2. FLAG-020 residue — the epistemology-bridge seam preamble

### What "the preamble class remains" is, mechanically

The freeze declarations are precise: the interception of CONTENT requests
is fixed, and the preamble class is not. Three distinct causes, all
verified in code.

**(2a) The fix landed in a classifier the bridge preempts.** The
FLAG-019/020 carve-out is a paragraph added to the *frame-breaker*
classifier prompt only:

```
# app/prompts/facilitator_prompts.py:339
A frame-breaker is also NOT a request addressed to the representatives for
content or for HOW they should answer … (FLAG-019/020 fix session,
2026-07-28: a table round's own-tongue request was wrongly intercepted
here and never reached the representatives.)
```

But the epistemology bridge is a separate classifier with the **highest**
priority in the chain:

```python
# app/graph/governance.py:114-119
# epistemology-bridge wins if it fired; else frame-breaker; else
# relational-safety - the sequential code's exact priority
out.is_frame_breaker = (False if out.is_epistemology_bridge
                         else frame_breaker_result)
```

Whenever the epistemology classifier fires, the carve-out is never
consulted. `FACILITATOR_EPISTEMOLOGY_BRIDGE_CLASSIFIER_PROMPT`
(`facilitator_prompts.py:583-604`) contains no equivalent carve-out, and
`classify_epistemology_bridge(message)` receives only the raw message
string — no seated composition, no addressee — so it has nothing to
condition a representative-aimed exception on even in principle.

**(2b) The classifier is told to over-fire, on a premise the battery
falsifies.** Line 599:

> "When genuinely unsure whether the double meaning is real, prefer
> EPISTEMOLOGY_BRIDGE … the cost of firing here is small: the
> Representative still answers the real historical question in the very
> next beat, just after a brief, honest word from the Facilitator first."

The stated cost model is that the preamble is additive. The Syriac
battery grading shows it is not. `batteries/S6.2_SYR_battery_A_grading.md`:

- item 5: *"turn 2's answer partially follows the Facilitator's injected
  documented-vs-reasoned frame rather than the participant's 'doesn't it
  bother you'"*
- item 13: *"the Facilitator seam-preamble fired on 2 of 5 turns and
  pulled the voice's frame toward documented-vs-reasoned epistemology —
  turn 5's fear question got the record-unevenness answer where the
  DEV-cleared response engaged fear directly"*

The classifier's own worked examples sit on the wrong side of the line
this battery tests. It lists *"How much of what you just told me is real
versus made up?"* (line 588) and *"How do you know what you know?"*
(line 590) as bridge cases, and *"How do your people know what you've
told me - what stands behind it?"* (line 593) as not. The battery's
source-awareness probe is
`A-src-1: "How do we actually *know* this is what your community
believed? What evidence backs it up — are you sure?"` — a near-neighbour
of both. **The RCF Part Eight `source-awareness` category and this bridge
are aimed at the same messages**: the category exists to verify that the
Representative answers evidence questions in-world, and the bridge
intercepts them.

**(2c) The real harm is the handback substitution, and it is separate
from the visible preamble.** `stream_epistemology_bridge` builds beat 2 by
appending a *fixed boilerplate* HumanMessage and never carries the
participant's own words forward:

```python
# app/graph/epistemology_bridge.py:137-147
handback_message = (
    "The participant just asked a question about the line between what's "
    "documented and what's inferred. Answer it about your OWN world only: …"
)
working_state = ConversationState(
    messages=list(state.messages) + [HumanMessage(content=handback_message)],
    retrieval_query_override=last_human_message,
    ...
```

`_prepare_representative_turn` then finds the *last* HumanMessage — the
boilerplate — and formats it into `REPRESENTATIVE_CONTINUATION_PROMPT`
(`nodes.py:972-976`, `1218`). The S3.5 `retrieval_query_override` fixed
retrieval only; **generation still never sees the participant's actual
question.** That is exactly the graded symptom in items 5 and 13, and it
is FLAG-020's original 2026-07-27 evidence (Papnoute answering the
bridge's attested-vs-reasoned frame and never engaging the patronage
substance) reproduced unchanged.

Note the contrast with the modern-term bridge, which does the same
substitution but *persists* its reframe as a `bridge_reframe` event so
§6.6's "every Representative reads the question actually asked" holds
(`modern_term_bridge.py:346-365`). The epistemology bridge emits no
reframe event at all, so the substitution leaves no trace in the
transcript.

**One further scope note:** `stream_epistemology_bridge` answers with a
single representative — `world_id = state.current_world_id or world_ids[0]`
(line 98). At a multi-world table the bridge structurally silences the
other seated voices for that turn, which is the mechanism behind
FLAG-019/020's TRR run-3 turn-7 finding ("the own-tongue request never
reached either representative").

### Recommended fix

**Fix A (the substitution — do this one first; it is the participant-facing
half).** In `epistemology_bridge.py`, carry the participant's question
into beat 2 instead of replacing it. Concretely: keep the
`state.messages` tail as-is and pass the epistemology constraint as a
`private_directive` on the `working_state` rather than as the last
HumanMessage —

```python
working_state = ConversationState(
    messages=list(state.messages),          # participant's own question stays last
    private_directive=(
        "The Facilitator has just spoken to the system-level half of this "
        "question. Answer the participant's own question as they asked it, "
        "from inside your world's own account of itself — what was witnessed "
        "and written down, and what you reason forward from silence, later "
        "custom, or a single voice's telling. Never describe how you are "
        "built or generated."
    ),
    retrieval_query_override=last_human_message,
    ...
```

`private_directive` already exists for precisely this (turn-local,
never persisted, never surfaced — `state.py:132-140`), and
`_prepare_representative_turn` already appends it last in the dynamic
prompt (`nodes.py:1198-1204`), which is where the S4.7/FLAG-018-layer-3
work established situational constraints hold best. This removes the
question substitution without touching the bridge's shape or the
Facilitator's beat.

**Fix B (the over-fire).** Two changes to
`FACILITATOR_EPISTEMOLOGY_BRIDGE_CLASSIFIER_PROMPT`:
1. Add the representative-aimed carve-out that
   `facilitator_prompts.py:339` already carries, worded for this
   classifier: a question about *how this world's own community* knew what
   it knew, or a request addressed to the representatives for content or
   for how to answer, is NOT_BRIDGE.
2. Replace the "when unsure, prefer EPISTEMOLOGY_BRIDGE" instruction and
   its cost rationale. The rationale is now known to be false — firing
   displaces the question, it does not merely precede it. Once Fix A
   lands, "when unsure, prefer NOT_BRIDGE" is the correct bias, matching
   the frame-breaker classifier's own discipline, with SELF_NARRATION
   monitoring as the documented second layer (the same fail-open the
   frame-breaker classifier already relies on, `nodes.py:404-418`).

**Fix C (observability, small).** Emit a `bridge_reframe` event from
`stream_epistemology_bridge` the way the modern-term bridge does, so a
future battery can see from the log alone whether the bridge fired and
what it handed back. Today the only signal is the
`classifier_decision` row, which records that it fired but not what it
substituted.

**Verification:** a deterministic classifier fixture in the shape of
`scripts/flag022_fixture.py` — the two committed live repros (Peter Brown;
the committee-voice probe) must classify NOT_BRIDGE alongside the four
RCF source-awareness probe strings; the genuine double-valenced set
("Where does documentation end and inference begin for you?", "How do you
decide what to say when you don't have a source?") must still classify
EPISTEMOLOGY_BRIDGE. Then re-run the source-awareness and
sustained-engagement categories of the Syriac battery, which is where the
four graded interference items live.

### Confidence

- **The priority inversion (2a): high.** Directly readable at
  `governance.py:118` against `facilitator_prompts.py:339`.
- **The handback substitution (2c): high.** The code path is short and
  fully traceable, and it predicts the graded symptom precisely.
- **That the classifier's over-fire bias is the firing cause on those
  four items: medium.** The classifier is a live LLM call; no
  per-item classifier input/output is preserved in the battery
  artefacts, so I am reasoning from the probe text against the
  classifier's own worked examples rather than from a captured
  decision. The over-fire instruction is certainly present and certainly
  points this way; that it decided these four specific items is inferred.

### Open question that needs a decision

**Should the epistemology bridge keep top priority in the chain?** It
currently preempts the frame-breaker, which means a message that is
*both* a genuine "are you an AI" and epistemology-shaped gets the bridge's
soft two-beat treatment rather than Section 12's "surface, answer,
recede." The docstring's original reasoning (`epistemology_bridge.py:41-49`)
is that the bridge should run only *after* the frame-breaker has said
"not a clear frame-breaker" — but the implementation runs all three
concurrently and then lets the bridge win, which is the opposite ordering
from the one the docstring describes. Reconciling the two is a design
decision about what the chain is for, not a bug fix, and it should be
settled before or alongside Fix B.

## 3. The table-craft calibration set

The Alexandria declaration groups these as one bullet:
misattribution/closing_synthesis/over_settling firing at medium on both
voices; dominance moderated 82%→70%; the drift-signal dedup defect;
FLAG-021-class seams. **They are not one root cause wearing several
names.** They are four separate things, of quite different kinds, and one
of them is not a defect at all.

### 3.1 The dedup defect — one clean mechanical bug, three call sites

Three table checks fan a single *round-level* finding out across
`spoken_this_round`, which is a turn-ordered list **with repeats**
(`main.py:1364`, `spoken_this_round.append(world_id)` once per turn):

| function | line | return shape |
|---|---|---|
| `check_convergence` | `nodes.py:2979-2990` | `for wid in spoken_this_round` |
| `check_question_stacking` | `nodes.py:3158-3171` | `for wid in spoken_this_round` |
| `check_manufactured_resolution` | `nodes.py:3546-3557` | `for wid in spoken_this_round` |

A six-turn round therefore emits **six identical signals** — which is
exactly the "×6 duplication" the ALX gate report names. Confirmed in the
committed SYR↔ALX TRR, rounds 4, 5, and 7, each carrying six
byte-identical `question_stacking` medium signals in the alternating order
`alx, syr, alx, syr, alx, syr` — the round's own turn order.

Second-order effect worth naming: the fan-out also *weights* a round-level
finding by turn count, so a world that spoke four of six turns gets four
copies of a finding that is by definition about the round.

**Recommended fix:** `for wid in dict.fromkeys(spoken_this_round)` at all
three sites (order-preserving distinct). Leave every *other* use of
`spoken_this_round` alone — `len(spoken_this_round)` is deliberately a
turn count in the round-window loops (`nodes.py:2921`, `3402`, `3476`),
and the `name_to_world` dict comprehensions dedupe already.

**Blast radius is smaller than it looks, and worth stating honestly.**
`queue_guidance` supersedes same-type entries for a world
(`governance.py:215-216`), so six duplicate `guidance_queued` events
collapse to one delivered directive. No representative was over-corrected.
The real cost is that `state.drift_signals` is inflated up to 6× and the
event log with it, which makes every drift-signal count in the freeze
reports unreliable as evidence — and directly touches FLAG-016's "17
declared vs. 20 emitted signals" bookkeeping.

**Confidence: high.** Code-verified and reproduced in the committed
artifacts, with the ×6 figure matching the mechanism exactly.

**A distinct, second duplication mechanism, not the same bug.** In the
ALX TRR round 8 the log carries four `misattribution high` signals (three
for Desert, one for Alexandria) and three `over_settling medium`. These
come from per-turn loops that are *correct* in principle —
`check_misattribution` iterates `round_turns` (`nodes.py:3408`) and
`run_post_round_governance` iterates the round's messages
(`governance.py:319`) — but they emit byte-identical descriptions for the
same world, which `queue_guidance` then supersedes down to one. Worth
collapsing per world at emit time for log hygiene; not the same defect as
the fan-out, and lower priority.

### 3.2 Dominance — a real threshold question plus a structurally inert half

`check_dominance` (`nodes.py:2813`) is two checks in one function.

**Word-share view** (`nodes.py:2874-2898`): fires at `share >= 0.70`,
severity `medium` below 0.80 and `high` at or above it. Against the
measured numbers, this reads plainly:

- Alexandria pre-fix, 77–82% → HIGH, every round.
- Alexandria post-fix, "moderated to 70%" → still fires, every round, now
  at medium. Confirmed in the committed ALX TRR run 3: `dominance medium
  alexandria-catechetical` in **7 of 8 rounds**.
- Syriac post-ceiling, 63% → below threshold, silent. Confirmed: zero
  dominance signals in the SYR↔ALX TRR.

So "moderated 82%→70%" means the fix moved one severity band and left the
finding firing continuously. The honest reading is that the ceiling fix
worked on *turn length* (139–246 words against 1053 pre-fix) and that
70% word-share at a two-world table is a separate question the ceiling
cannot reach.

**Floor-allocation view** (`nodes.py:2857-2872`): gated on
`len(world_ids) >= 3 and total_turns >= 6`. **Every TRR the fleet has run
is a two-world table, so this half has never executed once.** It was
written for exactly the FLAG-026 round: Theon held two of the round's three
turns — 67% of the floor, opening *and* closing — and no dominance signal
of any kind fired. The same pattern explains why `closing_synthesis` is
attributed to Alexandria in five of eight ALX TRR rounds: Theon is the
round's last speaker almost every time, and nothing watches floor
allocation below three seated worlds.

**Recommended fix:** lower the floor-allocation gate to `len(world_ids)
>= 2` and raise its share threshold for the two-world case, because at two
worlds a 50% turn share is the expected outcome rather than a finding.
A defensible starting pair, stated as unvalidated calibration in the same
way the existing comment states its own: fire at `>= 0.65` of turns when
two worlds are seated and `total_turns >= 4`, keeping `>= 0.50` at three or
more. That makes Theon's 2-of-3 visible without flagging a clean
alternating round.

**Confidence: high on the diagnosis, low on the specific numbers.** The
inert gate and the 0.70 boundary behaviour are code facts confirmed
against three runs. The proposed 0.65/4 pair is a starting point drawn
from three tables' worth of data, not a validated threshold — it belongs
in S6.6's threshold decisions with the rest.

### 3.3 The "mediums on both voices" — mostly the checkers working, with one factual correction

This item is **evidence, not defect**, and the Alexandria declaration
already says so ("the S4.7 checkers doing their designed job"). Two things
worth recording precisely:

- **Severities are hardcoded, not calibrated.** `over_settling` is always
  `medium` (`nodes.py:2018`, with the reasoning stated in the comment
  above it); `closing_synthesis` is always `medium` (`nodes.py:3610`);
  `misattribution` is always **`high`** (`nodes.py:3450`). The
  declaration's phrase "misattribution/closing_synthesis/over_settling
  guidance firing at medium" is slightly off for misattribution: the
  committed ALX TRR shows it at `high`, seven times. Small, but it changes
  how the item reads — a `high` firing seven times in eight rounds is not
  a calibration medium.
- **"On both voices" is by design for two of the three.**
  `check_convergence` and `check_manufactured_resolution` attribute to
  every speaker deliberately ("convergence is a relationship between
  voices, not one representative's individual fault", `nodes.py:2977`).
  `closing_synthesis` attributes to the last speaker only and
  `misattribution` to the characterizing speaker only, so those two
  appearing on both voices means they genuinely fired for each, in
  different rounds.

**What actually is loose here, and it is shared:** nothing closes the
loop. A finding is detected post-round, queued, delivered once as a
private directive on some later turn, and no mechanism checks whether the
next turn complied. Both the Alexandria and Syriac gate reports say this
out loud in the dominance case — "dominance signals firing every turn, not
obeyed" — and `HARD_CEILING_WORLDS` exists precisely because advisory
guidance did not bind on length. That is the one genuine common thread
across the calibration set, and it is a design gap rather than a bug.

**Recommended fix — the smallest useful version.** Do not build a
compliance engine. Instead, in `run_post_round_governance`, when a
`guidance_consumed` event for `(world_id, signal_type)` is followed by the
same `signal_type` firing again for the same world in the next round,
append a `guidance_ineffective` observability event carrying both round
indices. That costs nothing at runtime, needs no new judgment, and turns
"firing every turn, not obeyed" from a grader's impression into a
countable fact — which is what S6.6's threshold work will need in order to
decide, per class, whether guidance is enough or a mechanical backstop is
required.

**Confidence: high** on the mechanism and the severity facts;
**medium** on the claim that non-compliance is the shared root, because it
is currently supported by two gate reports' qualitative observations and
one mechanical fix (the ceiling) rather than by a measurement. The
recommended event is what would settle it.

### 3.4 An unflagged finding in the same family: cross-world vocabulary drift is largely inert on migrated worlds

Found while tracing why Theon's round-1 use of *shrara* produced a
`fabrication` signal rather than a `cross_world_vocabulary` one.

`check_cross_world_vocabulary_drift` builds its term list per world
(`nodes.py:3274-3279`):

```python
def _terms_for(wid: str):
    records = _term_records_for_world(wid)
    if records:
        return [(t[0], f"Period sense: {t[3]}\nQuick meaning: {t[2]}")
                for t in records if t[0]]
    return _get_world_lexicon_terms(wid)
```

`t[0]` is the record's raw `term` frontmatter field, used **verbatim** as
a word-boundary regex (`_term_boundary_pattern`, `nodes.py:3177`). But
that field is a composite display string. From the committed records:

- `syriac_world`: `term: raza (ܐܪܙܐ) / shrara`, `term: qyama (ܩܝܡܐ) / bnay
  qyama / bnat qyama`, `term: Iḥidaya (ܝܚܝܕܝܐ)`, `term: Mar (ܡܪܝ)` …
- `desert_world`: `term: Apatheia (Passionlessness)`, `term: Logismoi (The
  Thoughts)`, `term: Hēsychia (Stillness)` …

`\braza\ \(ܐܪܙܐ\)\ /\ shrara\b` matches nothing in prose. Counting the
committed records:

| world | term records | matchable as written |
|---|---|---|
| Syriac | 10 | **0** |
| Desert | 18 | **0** |
| Alexandria | 50 | 28 (the bare-string ones) |

The legacy path already solves this. `_get_world_lexicon_terms`
(`nodes.py:3202`) routes every raw term field through
`_extract_term_candidates` (`nodes.py:3186`), whose docstring names this
exact failure — *"Matching that whole string verbatim against a
Representative's own ordinary speech never matches anything"* — using
`"qyama (ܩܝܡܐ) / bnay qyama / bnat qyama"` as its worked example. The
migrated path added at S4.7 bypasses it, and also discards the `aliases`
list the records carry at `t[1]`.

Consequences, in the direction that matters most:

- **Desert's and Syriac's distinctive vocabulary — apatheia, logismoi,
  hēsychia, qyama, raza, Iḥidaya — cannot be detected as a borrowing by
  any other seated world.** The Syriac freeze declaration's
  "*Vocabulary borrowing:* none" rests on human grading, which stands on
  its own; the automated checker that was meant to back it was blind for
  that direction.
- The check simultaneously runs *noisy* in the other direction:
  Alexandria's 28 matchable terms include "Scripture", "Death", "Prayer",
  "Fasting", "Baptism", "Christ", "Salvation", "Interpretation",
  "Participation" — ordinary Christian words that will pre-filter-match
  nearly every Desert or Syriac turn and spend a monitoring LLM call each
  time on the INVOKING/INCIDENTAL judgment. That is why "Theosis" fired at
  SYR↔ALX turn 7 while *shrara* could not.
- A second, smaller gap in the same function: `round_turns` is a dict
  keyed by world and populated with only the **most recent** turn per
  world (`nodes.py:3257-3263`). In a six-turn round, a world's earlier
  turns are never inspected at all.

**Recommended fix:** route the migrated branch through the function that
already exists —

```python
return [(cand, f"Period sense: {t[3]}\nQuick meaning: {t[2]}")
        for t in records if t[0]
        for cand in _extract_term_candidates(t[0])]
```

— and consider extending the candidate set with the record's `aliases`
(`t[1]`), which carry further real word-forms (`razā`, `rāzā`). Then
re-baseline: this will materially increase pre-filter hits, so the
INCIDENTAL judgment carries more load and its cost should be measured
before this is called done.

**Confidence: high.** The composite term fields, the unsplit regex path,
and the existing `_extract_term_candidates` helper are all directly
readable, and the observed firing pattern (Alexandria's bare terms fire,
Syriac's composite ones do not) is exactly what the code predicts.

**Open question:** whether this becomes its own FLAG entry. It is a
defect in a previous step's output (S4.7's migrated-world branch) that no
gate covers, which is Session Contract rule 6 territory. I have not filed
it — filing is the build session's act, not this investigation's — but it
should be filed rather than folded silently into the calibration bullet,
because it is a different kind of thing from the four items that bullet
names.
