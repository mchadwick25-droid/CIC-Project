  the §3.0 envelope + all 13 record types, every field and controlled
  vocabulary per Pass 1 §3.0–3.12; per-element `$comment` carries the Pass 1

  (`fixture-world`) and clearly marked.

## Non-vacuity proof

A seeded-invalid `term` record (bad register, tier 9, string where boolean,
undeclared field, unwarranted relation type, em-dash sentinel in
`retrieve_when`) fails with **6 errors**, each naming its violation —
including the sentinel check, which is the validator's own rule on top of
JSON Schema. (The full seeded-defect battery for gates is S1.3's job; this
proves the S1.5 validator itself is not vacuously green.)

## Structural-floor note (deliberate)

The schema requires only `id`/`world_id`/`record_type`/`schema_version`
structurally; §11-A requiredness (per type, per stage, with backfill
profiles) is the S1.3 field-completion gate's job — encoded there so
"green" under backfill mode is honest rather than lenient (blueprint S2.1).

Dependency note: `jsonschema` is installed in the backend venv for this
validator only — the app runtime never imports it; `requirements.txt`
deliberately untouched (outside S1.5's declared file set).
