## 0. How to use this blueprint — the session contract

This blueprint is executed by **Sonnet sessions, one step at a time** (per the standing model-tier allocation: Sonnet builds and compiles; Opus runs review passes; Fable is not in the execution loop). Every build session follows the same contract, and the contract is the first defense against the failure this whole redesign exists to fix — because incremental session-by-session building is exactly the process shape that produced the fan-out/drift record (a fix landing where the reviewer looked while the same fact stayed stale elsewhere; a claimed fix that was never delivered; a companion artifact never regenerated).

**The session contract — every build session, no exceptions:**

1. **Read the build-state ledger first** (`Ministry/Technology/Pass2/BUILD_STATE.md`, created in step S1.0). It names the current step, the last completed checkpoint, and any parked items. A session never relies on memory of a previous session — all state lives in committed files.
2. **Re-run the previous step's checkpoint before starting your own work — what "re-run" means depends on the checkpoint kind, stated here so no session has to guess.** For G/B checkpoints (deterministic scripts): literally re-execute the script; it must reproduce the same result. For content-coverage parity: literally re-diff. **For R, P (probe-parity), and L checkpoints, which depend on a specific sample, a specific set of held-out probes, or blind grading — "re-run" means re-checking the artifact's own committed sample IDs, probe list, or battery transcript against the underlying records/code, not drawing a fresh sample or re-blind-grading with different material.** The committed artifact must include those IDs/lists for exactly this reason — an artifact that only states a verdict, with no way to re-derive it against the same rows, does not satisfy this rule. If the previous checkpoint no longer passes under this check, stop: the step is not "do my step anyway," it is "file the regression and halt." This is how a claimed-but-not-delivered fix gets caught at the next session instead of three worlds later.
3. **Do one step. Only that step.** The step spec names every file it is allowed to touch (`Touches:`). Changing a file outside that list is not forbidden by the tooling — it is caught by the checkpoint reviewer, whose first structural check is the diff against the declared file set. The fan-out list is precomputed *here*, not left to session judgment.
4. **Never edit a gate or checkpoint script in the same session that must pass it.** Gate changes are their own steps with their own review. A session that needs a gate changed to pass files a flag and stops.
5. **A step is done when its checkpoint artifact exists, is committed, and re-runs green — not when the session says so.** The checkpoint definition lives in this blueprint, written before any session ran; the executing session cannot move its own goalposts.
6. **If you find a defect in the Pass 1 design, in this blueprint, or in a previous step's output: stop and file it** (append to `Ministry/Technology/Pass2/FLAGS.md`, with the evidence). Never silently patch around it, never silently fix it in passing. Whether to change course is Mark's call or a review-round call, not a mid-session judgment.
7. **End every session deployable.** No step leaves the running system half-migrated. The compatibility rule (§3.2) exists so this is always possible. If a session runs out of room mid-step, it commits what is consistent, marks the step `in-progress` in the ledger with a note on exactly where it stopped, and the next session restarts the step *from the last green checkpoint* — not from a description of partial work.
8. **Every step's outputs are committed with the step ID in the commit message.** The ledger, the commits, and the checkpoint artifacts are the same story told three ways; a mismatch between them is itself a filed flag.

**Why this contract is shaped this way:** the six-world defect record shows written rules alone failing repeatedly (a standing rule against self-certification was adopted at the second world built and the identical pattern recurred in the third, fourth, and sixth). So this contract leans on the same conversion Pass 1 §4.2 makes for build gates: **everything that can be a program is a program** (re-runnable checkpoints, declared file sets, committed artifacts), and what can't be a program is an *independent* review with a saved artifact — never the builder grading their own work.
