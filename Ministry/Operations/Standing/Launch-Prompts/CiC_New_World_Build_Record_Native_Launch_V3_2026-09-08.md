# Launch prompt — Record-Native World Build (V3, 2026-09-08)

**V3 change (Mark's ruling, 2026-09-08, streamlining for scale — "if we
are going to build 100 worlds this has to be streamlined"):** V2's gate
list assumed two things that are no longer true: that the build thread
has no network access (so Mark manually downloaded and attached every
source), and that every gate needed a stop even where nothing real was
left to decide. Both are now false — network access is confirmed
working directly in the build environment, and the fleet has enough
precedent (Donatism, Latin Pastoral-Congregational) to show which gates
were actually load-bearing decisions versus which had become a drip of
approvals with no real choice in them. Mark's own words: *"I only want
to engage when I am truly needed for a decision... this has to be
streamlined."* Three structural changes from V2:

1. **G1 (source acquisition) is self-disposed, not gated.** The build
   thread finds, rights-checks, fetches, and vendors sources directly —
   no manual download-and-attach loop, no per-source approval. It
   escalates to Mark only when a source is genuinely inaccessible to it
   (paywalled, physical-only, requires purchase) — a real, narrow
   request, never a blocking halt on the rest of the build.
2. **G3 (the voice bar read) is non-blocking.** Opus/Fable run the
   register-bar comparison automatically against the approved sample as
   part of the standard review loop, and the build proceeds if it
   clears. Mark can spot-check any world's voice himself at any time —
   it just never halts the pipeline waiting on him. (This is a real
   quality-vs-throughput tradeoff, not a free simplification — V2 called
   this "the read that set the pilot's quality"; the tradeoff is made
   knowingly, at Mark's own instruction, not defaulted into.)
3. **G0 can be pre-cleared by an existing decision record.** Where the
   portfolio-admission question (world, window, Atlas placement) has
   already been argued through and decided in conversation with Mark
   before the launch prompt is written — as happened for Gaul/I.27 on
   2026-09-08 — the launch prompt cites that record instead of
   re-opening the question inside the build thread. G0 remains a real
   stop for any world where that groundwork has NOT already happened.

**What stays a real stop, unchanged from V2, because each is a decision
only Mark can make and the fleet's own process treats it as such, not
as a formality:**

- **G2 — Representative identity.** Name and role. Grounded options, one
  recommendation each, his actual choice recorded — every option checked
  first against `Ministry/Technology/CiC_Representative_Naming_Role_Discipline_2026-09-08.md`'s
  five tests (real-but-not-confusable, lands with a modern reader, role
  spans the whole movement not a moment in it, name/image are the only
  fabrications and neither may bias what gets represented, and — where
  women were genuinely significant in the movement — a woman's name is a
  real candidate, checked for the same whole-movement fidelity as any
  other). Read that document in full before drafting G2 options for any
  world.
- **G4 — Article 29 (living-tradition) determination.** A policy call
  about presenting connection to a still-living denomination.
- **G5 — Admission & freeze.** *"Only Mark assigns Frozen"* is V2's own
  language and does not change — the battery evidence and a completion
  summary are pre-run and handed over as one finished package, not a
  drip of asks.
- **Manual imports** the build thread genuinely cannot reach itself.

Everything else in V2 not named above carries forward unchanged: the
birth conditions (register bar, transparency ground, file discipline),
the Source Acquisition Manifest format, model routing, the cost
discipline, and the completion handoff. Read V2
(`Archive/Ministry-Early-Days-2026-07/Operations/Standing/Launch-Prompts/CiC_New_World_Build_Record_Native_Launch_V2_2026-08-30.md`) for that
full text — this document states only what changed and why; it does not
duplicate what didn't.

## What this thread does

Build the named world end-to-end — Step-0 confirmation (or its
pre-cleared record) through a drafted freeze declaration — **born
record-native and born at the bar**, under
`reference/method/CiC_Record_Native_World_Build_Process_V1.8.md`,
with the gate changes above in force.

Read IN FULL, in this order, before any work:

1. This document (what changed and why).
2. V2 in full, for everything that did not change — the process
   sequencing, the register bar, the completion standard, the
   Construction Framework V7.4, the RCF V3.2, `SESSION_CONTRACT.md`, and
   the cic-build-cycle discipline (CO-022).
3. Whatever G0-pre-clearance record the launch prompt cites, in full —
   not a summary of it.

## Running without per-document stops

Between G2, G4, and G5, the thread does not pause for approval on
individual documents, review rounds, or fix passes. CO-022's own
self-disposition discipline already covers this — a document that
clears review with no escalation-category finding is the build thread's
own to dispose, exactly as Doc_01–Doc_10 and their review rounds already
work in the fleet. Streamlining under V3 means not inventing a stop
where the process never required one, not loosening what CO-022 already
requires disclosed and logged. The four standing escalation categories
still apply at any point regardless of gate position — identity/name/
title changes, portfolio-level decisions, governance or methodology
changes, and unresolved tensions the pipeline cannot close. An
escalation is not a "gate reintroduced"; it is the pipeline correctly
recognizing a real decision when one actually appears, which is exactly
what Mark's own instruction asks for — engagement when truly needed, not
never.
