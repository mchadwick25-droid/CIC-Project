# Launch prompt — Messaging & Branding Kit thread

Paste this into a fresh thread. This project has produced strong individual pieces of
public-facing language — elevator speeches, a landing page draft, a refreshed Letter to
Friends, an FAQ refresh, a launch plan — but each was written on its own, at different
times, by different passes. Nobody has yet built the thing that makes all of them sound
like they come from the same project: a real messaging and branding kit.

**The task, stated exactly as given:** go through a thorough process of building a full
messaging and branding kit.

**Scope note:** this thread produces the kit — voice, message architecture, and visual
identity basics — as a reference artifact. It does not rewrite the existing comms drafts
itself (that's a follow-on once the kit exists to write against) and it does not touch
`cic-poc` code or design UI screens (that's the separate Front-End Graphics thread,
launched alongside this one — coordinate but don't duplicate).

---

## What already governs this, read in this order

1. **`Ministry/Communication/Vision, Mission, Convictions, and Foundational
   Commitments V1.1.docx`** — the Why, and the actual constraint on tone. Two things
   bind this thread specifically:
   - **Stewardship Over Optimization** — messaging that's punchy but overclaims what
     the project or its Representatives can do fails this standard even if it converts
     well. The kit's voice guide must make honesty-over-persuasiveness an operating
     rule, not an afterthought caught in review.
   - **Historical Responsibility** — the same discipline that governs a Representative's
     claims (never invented, never oversold, absence stated plainly) applies to how the
     project describes itself publicly. A brand kit that oversells "talk to history
     itself" without the epistemic humility the product actually practices would be the
     project's own marketing contradicting its own Article 6 standard.
2. **`L1-Foundation/CiC_L1_Constitution_V2_2.docx`**, Article 6 (Encounter-Success
   Standard) — already governs every public-facing artifact in this project; the kit's
   voice guide should make explicit how public messaging stays consistent with it
   (no claims a Representative wouldn't itself make about its own reliability).
3. **The existing comms corpus — read all of it before drafting anything new,** since
   the kit's job is to name the voice that's already implicitly present in this work,
   not invent one from nothing:
   - `Ministry/Communication/CiC_Elevator_Speeches_V0_1.docx`
   - `Ministry/Communication/CiC_Landing_Page_Copy_V0_1_DRAFT.md`
   - `Ministry/Communication/CiC_Letter_to_Friends_REFRESH_V0_1_DRAFT.md`
   - `Ministry/Communication/CiC_FAQ_REFRESH_V0_1_DRAFT.md`
   - `Ministry/Communication/CiC_Telling_The_Story_Launch_Plan_V0_1_DRAFT.docx`
   - `Ministry/Communication/Church_in_Conversation_Letter_to_Friends.docx` and
     `Church_in_Conversation_FAQ.docx` (the pre-refresh originals — useful for seeing
     what changed and why)
4. **`Ministry/Funding/CiC_Org_Funding_Decision_Log.md`** and
   `Ministry/Technology/CiC_FrontEnd_Decision_Log.md` — audience-relevant context: who
   this project is actually talking to at each stage (donors, reviewers, testers,
   church partners, the general public) differs by document, and the kit needs to name
   that rather than assume one voice fits every audience unchanged.

## What to produce

1. **A brand voice guide** — 3-5 concrete, checkable traits (not adjectives like
   "warm" alone, but a rule a future writer can test a sentence against), grounded in
   what the existing corpus already does well and where it's currently inconsistent.
   Include an explicit "we would never say X" list, the same discipline the project
   already uses for what a Representative refuses.
2. **A message architecture** — the one-sentence core claim, 3-4 supporting messages,
   and how they flex by audience (donor vs. reviewer vs. general public vs. a
   participant arriving cold) without contradicting each other or overclaiming per
   audience. Reconcile against the elevator speeches already drafted — name where they
   agree and where the kit adjusts them.
3. **Visual identity basics** — name, wordmark treatment, a color palette, and
   typography direction sufficient for the Front-End Graphics thread and any print/web
   materials to work from consistently. This does not require a finished logo if none
   exists yet — say plainly what's decided, what's a placeholder, and what's still
   open, rather than presenting a placeholder as final.
4. **A one-page quick-reference** — the thing an outreach thread (funding asks,
   landing page, a partner conversation) can actually open and use in five minutes,
   distinct from the full kit's reasoning.
5. **A gap list** — where the existing comms drafts should be revised once the kit
   exists, named plainly as a follow-on task list, not rewritten by this thread itself.

## Coordination boundary, stated plainly

This thread builds the kit. It does not:
- Rewrite the existing comms drafts — name the gaps, hand them back.
- Design UI screens or app graphics — that's the Front-End Graphics thread's job;
  coordinate on color/typography so the two don't diverge, but don't duplicate its
  output.
- Make funding, org, or legal-naming decisions (entity name, trademark) — flag those as
  questions for Mark if the branding work surfaces one, don't decide them here.

## Logging

Log real decisions and open questions in
`Ministry/Communication/CiC_Messaging_Branding_Kit_Decision_Log.md` as they happen —
same dated-entry discipline used everywhere else in this project (what was decided, the
reasoning including the heart of it, the next action). Don't let a real decision live
only in this thread's own conversation history.
